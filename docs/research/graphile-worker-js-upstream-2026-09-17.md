No competing open upstream-port PR exists; the open release PR is unrelated and untouched.
- Live refs, tags, CHANGELOG, release metadata, merged PRs, source and tests were inspected. **Merged but unreleased: none after v0.18.0 at the observed refs.** Open [#633](https://github.com/graphile/worker/pull/633) (explicit migration entrypoints) and [#634](https://github.com/graphile/worker/pull/634) (Joi dependency) are proposals, not merged behavior.

## Implementation and compatibility

Ports: named-queue batch deduplication (#622), task/queue identity preservation (#623), bounded fetch-SQL text caching (#627), observer panic containment (#557), SQLx persistent-statement opt-out (#474), relevant operational documentation. PostgreSQL 16/17/18 CI expansion (#625) is prepared but blocked separately by GitHub workflow-scope authorization.
The touched database crate also declares its Tokio macros/time dependency features
explicitly, repairing a pre-existing standalone rustdoc build error visible in
[baseline Release-plz](https://github.com/leo91000/graphile_worker_rs/actions/runs/35191234068)
(`tokio::select!` unavailable without dev-dependency feature unification).

Migration 21 appends to the Rust history; migrations 1–20 are byte-for-byte unchanged. It preserves advisory key locks, GWNOR handling, worker recovery data and applied ledger rows. The official Node revision-20 fixture is covered separately from Rust revision 20. See [ADR 0002](../adr/0002-upstream-018-sync.md) and [compatibility](../src/reference/compatibility.md).

The inspection checkpoint and implementation coverage are separate: inspecting the head does not assert parity for all behavior predating v0.16.6, all JavaScript APIs, all OSs, or every mixed-worker deployment. Existing Rust-specific recovery, retryable-failure batching, task APIs and shutdown contracts remain intentional differences. No production databases, releases or tags are manipulated.
